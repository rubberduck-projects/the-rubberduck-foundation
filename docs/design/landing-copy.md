## 2. Why we exist

**Eyebrow**
Why we exist

**Heading**
Most of what makes a developer good is never written down.

**Lead**
It lives in a senior engineer's head, in a private chat, in a course that costs a month's rent. Not because it is hard to write down, but because keeping it written and current rarely pays. 

**Body**
The Rubberduck Foundation writes it down and puts it where anyone can reach it. Knowledge kept private stays small. Knowledge shared and maintained keeps growing.

### Why a rubber duck?

1. **Saying it out loud shows its shape.**
   Explaining a problem forces its structure into the open, often before you reach the end of the sentence.
2. **The duck never makes you feel stupid.**
   No question is too small to ask. That is the kind of place we are building.
3. **Explaining it is how you know you learned it.**
   That is why every article ends by asking you to say it back in your own words.

### Mission

**Quote**
To help people learn, build and connect, by the easiest path that still leaves something worth keeping.

## 3. What we build

**Eyebrow**
What we build

**Heading**
Learn, build, connect.

### Learn

* Status: Open now
* Title: Paths that tell you where you stand.
* Body: Short articles in a deliberate order. Each one says what you need to know first, what you will be able to do after, and when it was last checked.

### Build

* Status: In progress
* Title: Start building in one sitting.
* Body: Working starter code and a sandbox where nothing is at stake, so you can find out whether an idea holds before you put real time into it.
* Points:
  * Starter code that runs the first time
  * A clear point where your part begins
  * A sandbox you can throw away

### Connect

* Status: In progress
* Title: Circles, not crowds.
* Body: Small groups around a topic, a technology or a city. Small enough that no one is anonymous, large enough that no one is a bottleneck.
* Points:
  * Open sessions and mentorship
  * A shared place for questions, answered within a day
  * Answers that stay searchable afterwards

**Closing line**
A path leads to a build. The build raises questions. A Circle answers them, and the best answers become the next path.


## 4. What we produce

**Eyebrow**
What we produce

**Heading**
Fewer things, kept working.

**Body**
We would rather make ten things a thousand people rely on than a thousand things nobody finishes. Everything is open to reuse, and every piece has a named person looking after it.

**Cards**

1. **Writing**
   Guides, articles and learning paths, written for the reader's next hour, not for search engines.
   Link: Start reading
2. **Playbooks**

   Link: Start reading

## 5. How learning works here

**Eyebrow**
How learning works here

**Heading**
Read it, try it, explain it to the duck.

**Lead**
Every trail has one destination and gets there in small steps. It works the same whether you are new to code or fitting this in between meetings.

**Steps**

1. **Pick where you want to end up**
   Each trail ends at one skill or one role, named in a single sentence.
2. **See the whole route**
   The big skills along the way, laid out in the order you need them.
3. **Take one small step**
   Each article teaches one thing in about two minutes, then gives you ten to practise it.
4. **Explain it to the duck**
   Say it back in your own words, then finish with a small project worth showing.

## 7. How we keep it working

**Eyebrow**
How we keep it working

**Heading**
If it is here, it still works.

**Lead**
Instructions go stale quietly. A step that worked in March can break by June. So every piece is dated, checkable and open to correction from anyone who reads it.

**Points**

1. **Every claim can be checked**
   It comes with a command to run, a test to pass or data to inspect.
2. **Every page shows when it was last checked**
   If something is out of date, we say so on the page instead of letting it mislead.
3. **Anyone can report a broken step**
   You only need to be right, not a maintainer.
4. **Corrections stay visible**
   When something was wrong, the fix and the note that it was wrong both stay public.
